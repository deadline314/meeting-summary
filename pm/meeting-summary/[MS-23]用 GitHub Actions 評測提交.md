# [MS-23] 用 GitHub Actions 評測提交

> 狀態：待辦

## 內文

### 需求
提交的程式碼要在隔離環境中執行並自動評分，結果可信、不可被學生偽造，成本維持在免費額度內。

### 來源
使用者 2026-10-19 對話（初始需求）；設計：`design/02-architecture.md` §6；決策：GitHub Actions

### 驗收條件
- [ ] 每次提交自動觸發一次評測，結果自動回寫到平台
- [ ] 學生程式在無網路、無任何秘密的環境中執行，有時間與記憶體上限
- [ ] 評測結果只接受經 GitHub 簽章驗證、來自指定 repo 與 workflow 的回報；偽造的回報被拒絕並記 log
- [ ] 評測程式沒產出結果、格式錯誤、逾時、記憶體超限時，平台判為錯誤或逾時並寫明具體原因
- [ ] 超過時限沒回報的工作由排程標記為逾時，不會永遠卡在執行中
- [ ] 公開的 Actions log、workflow 輸入、artifact 中沒有任何學生程式、輸出、分數或秘密（只有工作 id 與耗時）
- [ ] 後台看得到本月評測次數與總耗時
- [ ] 有一份文件說明如何設定觸發評測用的 GitHub 權杖與 workflow 權限
- [ ] 本機開發不需 GitHub 也能跑完整評測流程

### 測試流程
1. 提交一份正確程式，在 GitHub Actions 看到工作執行，平台顯示通過
2. 提交一份會嘗試連網的程式，執行時無法連網
3. 提交無窮迴圈程式，超過時間上限被判逾時並顯示原因
4. 用 curl 偽造一筆評測回報，平台拒絕
