# 任務模組（類似 Kaggle）

> 來源：使用者 2026-10-19 對話。決策：評測在 GitHub Actions 執行（架構見 `02-architecture.md` §6）。

## 1. 物件

| 物件 | 重點 |
|---|---|
| 任務 | 標題、說明（Markdown，可放圖）、開始與截止時間、可見對象（全站／指定專案）、提交格式（檔案、程式碼、壓縮檔）、檔案大小上限、每日提交上限、是否開放排行榜、分數方向（越高越好／越低越好） |
| 評測設定 | 評測程式（老師上傳）、隱藏資料、執行環境（預設 Python 映像檔＋需求套件清單）、時間／記憶體上限 |
| 提交 | 學生、時間、檔案、狀態（排隊中 → 執行中 → 通過／未通過／錯誤／逾時）、分數、原因、執行紀錄（截斷） |

## 2. 老師／管理員流程

1. 建立任務 → 寫說明 → 上傳評測程式與資料 → 設定上限。
2. **試跑**：用老師自己的範例提交跑一次，確認評測程式能跑、結果格式正確，才可以發布。
3. 發布後可修改說明與截止時間；改評測程式時可選「對既有提交全部重新評測」。
4. 看所有提交、每位學生的最佳分數、未通過原因分布；可下載提交檔。

## 3. 學生流程

1. 任務列表看到「進行中／已截止」、自己的最佳成績與狀態。
2. 上傳檔案或貼上程式碼 → 即時看到狀態變化（排隊中、執行中）→ 結果出來顯示分數或未通過原因、執行紀錄。
3. 看自己的提交歷史；排行榜（若開放）只顯示每人最佳成績。

## 4. 評測程式合約

評測程式讀取提交目錄、輸出 `result.json`：

```json
{ "passed": true, "score": 0.913, "message": "準確率 91.3%", "details": [{ "name": "test_case_1", "passed": true, "message": "" }] }
```

- 沒通過時 `message` 必填，直接顯示給學生。
- 沒產生 `result.json`、格式不對、執行逾時、記憶體超限：平台自動判為「錯誤」或「逾時」，並寫出具體原因（例如「執行超過 300 秒上限」）。

## 5. 與其他模組的連結

- 會議紀錄可引用任務 `#[task:id]`，任務頁顯示「被哪些會議紀錄提及」。
- 議題可連結任務；任務頁看得到相關議題。

## 6. 未來：訓練模型

訓練工作沿用同一套工作流程，差在：執行時間長、需要 GPU、要回報過程中的指標（loss 曲線）與產出物（模型檔）。屆時把 runner 換成實驗室 GPU 機器的 self-hosted runner，並在提交頁加上即時指標圖。
