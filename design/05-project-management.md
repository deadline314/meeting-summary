# 專案管理模組：整體設計與重點（給其他專案參考）

---

## 1. 定位與設計原則

**定位**：做一套 Linear 風格的議題追蹤。專案底下放議題，用清單、看板、時間圖三種檢視管理進度。

**兩個不能妥協的需求**：
1. **專案層級的權限**：不是成員就完全看不到。
2. **完整的活動紀錄**：誰在什麼時候把什麼從 A 改成 B，全部只增不刪，供稽核用。

**貫穿整個設計的原則**：

| 原則 | 具體做法 |
|---|---|
| 只有一個事實來源 | 網頁、Chat AI、外部 MCP 三個入口呼叫同一組 service，共用同一套權限檢查和活動寫入，任何入口都不能繞過 |
| 不洩漏存在與否 | 非成員存取專案一律回「找不到」（404），不回「無權限」 |
| 狀態全放在 URL | 檢視、篩選、排序都寫在 URL，重新整理、分享連結、瀏覽器返回都能還原畫面 |
| 同一個動作只定義一次 | 快捷鍵、右鍵選單、指令面板、tooltip 角標全部從同一份動作清單渲染 |
| 不刪資料 | 專案、議題、留言都是軟刪除；專案要先封存，才能永久刪除 |
| 主流程不能被旁支拖垮 | 通知、mention 解析、Email、Slack 失敗都只記 log；但涉及安全的清理失敗要丟錯 |
| 兩種主題從第一天就一起做 | 顏色只用語意 token，禁止寫死色碼；每次驗收深淺主題各截一次圖 |

**刻意不做（v1）**：Sprint／Cycle、Roadmap、Triage、SLA、和 Git 分支自動連動。另外沒有票數上限，這正是當初從 Linear 免費版遷移過來的痛點。

## 2. 資訊架構與版面

```
┌ 全站導覽列 ┬ 專案側欄 ─────────────┬ 主區 ───────────────────────────┐
│ Projects  │ 我的 Issues          │ 工具列：檢視切換｜已存檢視｜統計     │
│           │ 時間圖總覽            │       篩選｜排序｜搜尋（/）｜新增（C）｜? │
│           │ 通知設定              ├────────────────────────────────┤
│           │ 專案 ＋               │ 清單／看板／時間圖                  │
│           │  ├ CATS 🔒 / 👥       │                                │
│           │  │  └ 子專案（縮排）   │                                │
│           │ 其他專案（僅管理員）    │                                │
│           │ 已結案（收合）         │                                │
│           │ 已封存（展開才載入）    │                                │
└───────────┴──────────────────────┴────────────────────────────────┘
```

**URL 結構**：

| 路徑 | 內容 |
|---|---|
| `/projects` | 我的 Issues：跨專案，列出指派給我的票 |
| `/projects/:key?view=list\|board\|timeline&status=…` | 專案頁 |
| `/projects/:key/:displayId` | 單張票，全頁 |

**側欄的可見度徽章**：🔒 私人、「僅成員」（已開啟對管理員隱藏）、👥 共享。hover 會說明誰看得到。

**決策（PROJ-44）：票券詳情只保留全頁，拿掉側邊抽屜。**
- 原因：同一個元件跑兩種寬度，每加一個區塊都要對兩次版，最後一定會長歪。
- 抽屜原本的價值是「不離開清單、連續掃票」。這個價值改用三件事補回來：
  - 全頁有上一張／下一張，順序沿用進來時的清單，包含當下的篩選和排序。
  - 返回清單時回到原本的捲動位置，並選中剛看的那張。
  - 直接用網址開啟、沒有清單脈絡時，不顯示計數和箭頭。

## 3. 概念模型

| 物件 | 重點 |
|---|---|
| 專案 | key 是 2–6 個大寫英文字母，全域唯一而且不能改；可以有子專案（樹狀，權限不繼承）；可設驗收人、目標日期；狀態有進行中、已結案、已封存 |
| 議題 | 編號是 `KEY-N`，每個專案用原子遞增的流水號，不用 `max+1`；負責人可以多位，第一位是主要負責人 |
| 狀態（6 種） | Backlog → Todo → 進行中 → 審查中 → 完成 → 已取消 |
| 優先級（5 級） | 緊急、高、中、低、無 |
| 父子票 | 一張票只有一個父票，最多 10 層，要檢查循環 |
| 關聯 | blocks、relates、duplicate_of；**blocked by 不另外存**，讀取時從 blocks 反推，避免兩邊寫入不一致 |
| 活動 | 結構化的 `{field, from, to}`，**存 id 不存顯示名稱**，人改名不會讓歷史紀錄錯亂 |
| 標籤 | 屬於單一專案；顏色存 token key，不存色碼 |

**時間圖和統計不另外建表**，全部從狀態變更的活動推導。資料只有一份，不會出現兩邊對不上的問題。

## 4. 權限與可見度

| 身分 | 能做什麼 |
|---|---|
| 非成員 | 看不到（回 404） |
| 檢視者 | 唯讀 |
| 成員 | 加上開票、改票、留言、上傳 |
| 擁有者 | 加上成員、標籤、設定、封存 |
| 站方管理員 | 所有共享專案都看得到、都能管理 |

**私人專案**：
- 判定是動態的：成員數 ≤ 1 就是私人專案。不用另存欄位，加一個成員就自動變成共享。
- 對管理員完全隱形；用 `<= 1` 是為了讓沒有成員的孤兒專案也被隱藏。

**對管理員隱藏**：只有身為擁有者的成員能開啟。

**跨專案查詢**（我的 Issues、搜尋、AI 工具）一律先算出「我可見的專案集合」再下查詢，不查完再過濾。事後過濾會讓分頁數量錯亂，也容易外洩資料。

**防呆規則**：
- 最後一位擁有者不能被降級，也不能被移除。
- 移除成員時，一併清掉他的訂閱、驗收人身分和負責人指派。
- 指派或 @ 一個人之前，先確認對方看得到這個專案。

**結案**：
- 驗收人、擁有者、管理員可以結案；必須走專用的結案動作，不能直接把狀態改成已結案。
- 權限檢查要放在狀態檢查前面，否則一般成員可以用 403 和 422 的差別，反推出專案目前的狀態。

## 5. 主要操作的設計

### 5.1 開票
- 開啟方式：按 `C`、工具列的「新增」、看板欄頭的「＋」（會預帶該欄狀態）。按鈕文字一律是「新增」，落在哪個狀態放在 hover 說明裡。
- 欄位：標題自動聚焦，描述是 Markdown。底部一排 pill，依序是專案、模板、狀態 `S`、優先級 `P`、負責人 `A`、標籤 `L`。
- 送出：`⌘/Ctrl+Enter`。勾「連續建立」後，送出不關視窗，並清空內容。
- 專案選單只列出「進行中」而且自己不是檢視者的專案。

**模板**：
- 範圍分個人、專案、全域；同時有多個預設時，優先序是個人 > 專案 > 全域。
- 描述是空的時候自動帶入預設模板。
- 換模板會**整份覆蓋描述，不跳確認視窗**，改用瀏覽器原生的 ⌘Z 當安全網。換模板是低風險、可還原的動作，每次都確認只會多一次點擊。
- 坑：要讓原生 ⌘Z 能還原，覆蓋時必須走原生輸入路徑。受控的 textarea 一旦被程式直接指派 value，undo 紀錄就會被清空。

**草稿保護**：
- 草稿自動存到 localStorage，重新開啟時提示「已還原上次未送出的草稿」。
- 打過字之後，Esc、X、點視窗外都會跳出三選一對話框：**取消／刪除／保留草稿**，焦點預設在「保留」。
- 決策紀錄：
  - 原本是「按兩次 Esc 才關閉」的兩段式。但使用者沒有機會說「這次不要留」，除非他知道底部有一顆「捨棄」按鈕。
  - 三選一對話框做成獨立元件，沒有去擴充全站共用的兩鈕確認框，免得十幾個既有呼叫端都要承擔風險。

### 5.2 清單與看板
- **看板**：
  - 6 欄；完成與已取消預設摺疊成窄欄。
  - 跨欄拖曳等於改狀態，欄內拖曳等於排序。排序用浮點數取中點插入，只寫一列。
- **清單**：
  - 依狀態分組，組頭可收合；欄位是優先級、編號、狀態、標題、標籤（最多 3 個，多的顯示 +N）、負責人、建立時間（hover 顯示絕對時間）。
  - 列上的 icon 可以直接點開選單就地修改；超過 200 列時改用虛擬化渲染。
- **每個狀態各自查詢、各自分頁**，一次 50 張。組頭顯示「已載入／總數」；收合的組不載入內容，但仍顯示總數。
  - 教訓（PROJ-53）：原本一次抓前 50 張再在前端分組。某個狀態的票如果全排在後面，那一組就**整組消失**，使用者回報「Todo 不見了」。
- **我的 Issues**：完成的票預設只列最近 14 天，組底有「顯示全部」可以切換。

### 5.3 被擋住的票要一眼看得出來（PROJ-50）
- 標題前加一段前綴：「擋住它的第一張票標題 +N ⃠ 本票」，用暖色顯示。hover 列出最多 5 張，點擊會開那張票。
- **擋住它的票全部完成後，前綴自動消失。**
  - 教訓：原本的計數把已完成的票也算進去。紅色提示一直亮著，等於一直告訴使用者「還不能動」，這比沒有提示還糟。
- 子票標題前也會標出父票，使用同一套前綴機制。

### 5.4 票券詳情（全頁）
- **左邊內容欄**，由上到下：
  1. 衝突橫幅（「這張 issue 已被其他人更新」＋重新載入）
  2. 父票 chip，以及「⛔ 被 N 張票擋住」
  3. 標題（就地編輯）
  4. 描述（Markdown；`- [ ]` 可以直接勾選）
  5. 子議題（x/y 進度條，行內按 Enter 就能新增）
  6. 關聯
  7. 附件
  8. 活動與留言合併的時間軸
- **右邊屬性欄**：狀態、優先級、負責人、標籤、截止日，另外顯示建立資訊和停滯徽章。
- **勾選待辦**：如果原文和畫面對不上，系統會拒絕改寫，避免勾錯項目。

### 5.5 留言與時間軸
- `@` 叫出成員、`#` 搜尋議題。存檔格式是 `@[user:id]`、`#[issue:KEY-N]`，畫面上渲染成 pill。被 `#` 引用的票會反向記一筆「被引用」。
- 回覆只有一層；只能編輯、刪除自己的留言，編輯過會顯示「（已編輯）」。
- 時間軸可以篩選全部、留言、變更，可以切換排序，用「載入更早」分頁。
- **輸入框自動長高，到 40% 視窗高度為止，不提供手動拖曳**。兩者會互相覆蓋，造成「拖大之後又自己縮回去」。
- 坑：用程式改寫 textarea 的值（自動接續清單、插入 mention），瀏覽器會把捲軸重設到底。必須先記住 `scrollTop`，還原選取範圍後再把游標捲回可視範圍。

### 5.6 附件
- **檔案存在上傳者自己的 Google Drive**，路徑是 `AI Desktop Projects/{KEY}/{KEY-N}`；資料庫只存 metadata 和連結。
  - 資料夾層級用 key 和票號命名，因為它們唯一而且不會變；標題會改名，uuid 又看不懂。
- 上傳方式有按鈕、貼上、拖放。**貼上或拖放圖片時會先開標註器**（紅框、文字、復原與重做）。
- **先傳檔，再登記**：上傳過程不寫資料庫，確認 Drive 上檔案存在之後才寫，所以中斷不會留下孤兒附件。之後任何一步失敗，就盡力刪回 Drive 上的檔案。
- **掛載既有的 Drive 檔**和上傳故意採用不同規則：
  - 不套大小上限。
  - 不自動改 Drive 權限。
  - 移除時永遠不刪來源檔。
- **分享政策**：自動路徑最多只開放到「公司同仁可檢視」；「知道連結的人」只能由使用者手動選擇，任何自動流程都不能放寬到這一步。
- 沒有連結 Drive 時，顯示引導和「連結」按鈕，不顯示錯誤。

### 5.7 複製此票
- 從右鍵選單觸發，可以改名稱，可以選要不要一併複製子議題、附件、標籤、負責人，也可以選目的專案。
- 範圍逐步擴大：最初需求只複製標題和內文，v2 才加入子樹、附件和跨專案。
- 編號一次預留一段給整棵子樹；複製 Drive 檔的期間不佔用資料庫交易。

### 5.8 專案生命週期
- 生命週期：進行中 → 已結案（可重新開啟）→ 已封存（可還原）→ 永久刪除。
- 永久刪除必須先封存，而且要**輸入專案 key 確認**。
- 專案 key 在永久刪除之前都不會釋放。
- 封存父專案不會連帶封存子專案。

## 6. 互動系統：同一個動作只定義一次

```
動作清單（id, 名稱, 按鍵, 作用範圍, 何時可用, 執行）
   ├→ 快捷鍵管理（單一 keydown 監聽 ＋ 範圍堆疊）
   ├→ 右鍵選單
   ├→ 指令面板（⌘K）
   ├→ 快捷鍵說明（?）
   └→ Tooltip 的快捷鍵角標
```

- **範圍堆疊**：開啟對話框時把它的範圍推上去，上層吃掉按鍵，杜絕「對話框開著時按 C 又開一個」。輸入框有焦點時，停用單鍵快捷鍵。
- **快捷鍵說明一定準確**：說明是從動作清單即時渲染的，所以列出來的按鍵一定當下可用。

**快捷鍵**：

| 按鍵 | 動作 |
|---|---|
| `C` | 開票 |
| `/` | 聚焦搜尋 |
| `J`/`K` 或 `↑`/`↓` | 移動選取 |
| `Enter` | 開啟議題 |
| `X` | 多選 |
| `S`/`A`/`P`/`L` | 改狀態、負責人、優先級、標籤 |
| `I` | 把自己加入負責人 |
| `⌘C` | 複製 ID |
| `⌘⇧C` | 複製連結 |
| `G B`/`G L`/`G T` | 切換看板、清單、時間圖 |
| `G O` | 全局時間圖 |
| `[`/`]` | 上一張／下一張 |
| `=`/`-`/`T` | 時間圖放大、縮小、跳到今天 |
| `⌘K` | 指令面板 |
| `?` | 快捷鍵說明 |
| `Esc` | 逐層關閉 |

**`S`/`A`/`P`/`L` 共用同一個選擇器元件**：開票視窗、右鍵選單、詳情頁三處都用它。

**指令面板**：上半部搜尋動作；下半部搜尋議題，可以打 `CATS-42` 或關鍵字。

**右鍵選單**：

| 情境 | 選單內容 |
|---|---|
| 共通 | 狀態、負責人、優先級、標籤子選單 |
| 單選另有 | 建立關聯（子票、父票、Blocks、Blocked by）、複製此票、複製 ID、複製連結、刪除 |
| 多選 | 標題顯示「N 張 issues」；負責人改為整組取代成一人；刪除顯示「刪除 N 張 issues」 |

**危險動作**：
- 一律用主題化的確認框，不用原生 `window.confirm`，因為原生框吃不到主題 token。
- 確認框裡要寫出後果，例如「移除後對方將看不到此專案與其中的 issues」。
- 坑：所有浮層都要帶同一個標記，Esc 才會先關最上層。少了這個標記，在確認框上按 Esc 會把底下的整個開票視窗連同草稿一起關掉。

## 7. 引導與可發現性

- **只有圖示的按鈕一定要有 tooltip**，並列入 code review 檢查清單。tooltip 延遲 400ms，並自動附上快捷鍵角標。
- **空狀態就是引導**：
  - 沒有專案：「建立第一個專案」。
  - 專案沒有票：「按 C 開第一張」。
  - 篩選後沒有結果：一鍵清除篩選。
- **新手引導 7 步**：私人與共享 → C 開票 → 時間圖 → 多位負責人 → 子票標出父票 → 指令面板 → 快捷鍵說明。狀態存在 localStorage，看過就不再自動跳出；在快捷鍵說明裡可以「重看新手引導」。
- **權限切換要有回饋**：專案在私人與共享之間切換時，toast 會說明現在誰看得到。

## 9. 追蹤輔助

- **時間圖**：每張票畫成「狀態時間段」。可以用 Ctrl/⌘＋滾輪以游標為中心縮放，級距有季、月、週、日；另有今天線、目標日期標記（逾期變紅）、截止日刻線。hover 顯示停留時間。單一專案最多 500 張票，超過會提示用篩選縮小範圍。
- **統計**：Lead time（建立 → 完成）、Cycle time（首次進行中 → 完成）的平均與中位數，各狀態平均停留時間，近 12 週每週完成數。
- **停滯偵測**：在同一個未完成狀態停留超過門檻（3/7/14/30 天，預設 7 天）就顯示 ⏰。依據是「狀態變更時間」，不是「最後更新時間」。
- **已存檢視**：直接把目前的 URL 命名存起來（上限 30 筆）。因為狀態都在 URL 上，這個功能幾乎不用額外成本。

## 10. 協作與通知

- **4 種事件**：被指派、狀態變更、新留言、被提及。自己做的動作不通知自己。
- **管道**：站內通知鈴鐺、Email、Slack Bot。Slack 訊息上有「開始處理」「標記完成」兩顆按鈕，按下後走同一個更新函式。
- **偏好設定**是「專案 × 事件」的矩陣，分進行中、已結案、已封存三區，有全選、全不選。**沒有設定資料就代表開啟**，新專案不需要初始化設定。
- **未讀紅點**：直接沿用通知表，「這張票有沒有未讀」就等於「這張票上有沒有我的未讀通知」。不另外建狀態欄位，避免同一個事實有兩份資料。
- **通知要等交易 commit 之後才真正送出**；每位收件人各自隔離，一個人失敗不影響其他人。

## 11. 可靠性設計

- **樂觀更新加樂觀鎖**：
  - 每張票帶 `version`。拖曳和改欄位都先改本地畫面，再送出請求。
  - 遇到 409 衝突就回滾，toast「已被其他人更新，已重新整理」，然後重新抓資料。
  - 批次操作失敗時彙整成一則「N／M 筆失敗，已還原」。
- **冪等寫入**：外部 AI 的寫入可以帶 `operation_id`，重送時不會重複執行。批次更新一次 1–50 張。
- **時間圖與統計的容錯**：資料是即時推導的，單張票的資料有問題就補預設值，不會拖垮整張圖。

## 12. AI 與外部整合

- **同一組 service 對外提供三種入口**：網頁 REST、Chat 內建工具、外部 MCP（Claude Desktop、Claude Code 等）。三者權限完全一致。
- **活動紀錄會標記來源**（chat、mcp、slack），稽核時看得出是誰透過什麼管道改的。
- **外部金鑰的權限**：分三級 scope（read、write、manage），也可以限定只能用特定專案。每次操作都重新讀取金鑰和帳號狀態，不信任快取。
- **Chat 回覆裡的票號**會渲染成可以點的膠囊；在 Chat 輸入 `#` 可以指定票，並存下當時的快照。

## 13. 實作和原設計不一致的地方（移植時請先決定要不要補）

| 項目 | 原設計 | 現況 |
|---|---|---|
| 通知對象 | 訂閱者收通知；建立者與負責人自動訂閱；60 秒合併 | 只通知負責人、被 @ 的人、被指派的人；訂閱只影響鈴鐺圖示；沒有合併 |
| 已結案專案 | 不能再開票 | 只有前端擋，後端照樣接受寫入 |
| 樂觀鎖 | 全面使用 | 專案和留言的 REST 修改可以不帶 version，不帶就是後寫的人贏 |
| 身分模擬的稽核 | 記下實際操作者 | 記成被模擬的人 |
| API Key 打 REST | 受 scope 限制 | 疑似只有 MCP 會檢查（未確認） |

## 14. 移植檢查清單

1. 先確定權限模型：成員角色、非成員回 404、私人專案怎麼判定、管理員能看到哪些專案。
2. 所有變更都經過**同一個 service**，並且在**同一個交易內**寫活動紀錄。
3. 編號用原子遞增的流水號；**blocked by 不另外存**；排序用浮點數取中點插入。
4. 狀態全部放在 URL；已存檢視直接存 URL。
5. 動作清單統一渲染快捷鍵、右鍵選單、指令面板、說明和 tooltip，並使用範圍堆疊。
6. 清單和看板都**每個狀態各自分頁**，組頭顯示「已載入／總數」。
7. 衍生提示（被擋住、停滯）**要排除已經完成的票**。
8. 顏色只用語意 token，深淺主題同時驗收。
9. 危險動作用主題化確認框並寫出後果；草稿關閉時給三個選項。
10. 附件「先傳後登記」，自動分享最多開放到公司網域。
11. 通知要在 commit 之後送出、每位收件人各自隔離、不影響主流程。
12. 如果要開放給 AI，就讓 AI 呼叫同一組 service，並在活動紀錄標記來源。
