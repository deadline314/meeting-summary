# 範例任務：每日天氣資料收集（真愛碼頭）格式驗證

學生交一天一列、24 欄的天氣資料表（CSV 或 XLSX），平台逐列檢查格式與數值。每個錯誤都標出**第幾列、哪一欄**，老師和學生按「檢視資料」就能看到檔案內容與錯誤位置。只用 Python 標準函式庫。

> 規則依作業文字整理。拿到 `sample_weather.xlsx`「欄位規格」與 `validate_weather.py` 後，若有不同（例如「資料來源類型」的可填值），改 `grade.py` 開頭的常數即可。

## 檔案

| 檔案 | 用途 |
|---|---|
| `grade.py` | 評測程式（上傳到「評測程式」）；也可以在本機當驗證腳本 |
| `make_samples.py` | 產生範例到 `samples/`：一份正確（跨 2022 換站）＋兩份帶錯（數值為合成，不是真實觀測） |

## 平台設定

建議開兩個任務：組員各自交件用一個，三份合併後的驗證用另一個。

| 欄位 | 組員各自交件 | 合併驗證 |
|---|---|---|
| 提交方式 | 檔案 | 檔案 |
| 允許的副檔名 | `.csv,.xlsx` | `.csv,.xlsx` |
| 檔案上限 | 10 MB | 10 MB |
| 評測程式 | `grade.py` | `grade.py` |
| 隱藏資料 | 不放（以檔案自己的第一天到最後一天檢查缺天） | `config.json`：`{"from": "2016-10-06", "to": "2026-10-06"}` |
| 時間上限／記憶體 | 60 秒／512 MB | 60 秒／512 MB |
| 每人每日提交上限 | 20 | 20 |
| 排行榜 | 關閉 | 關閉 |
| 分數方向 | 越高越好（沒有錯誤的天數比例 0–100） | 同左 |

三人負責的區間不同，所以組員任務不放 `config.json`，改用每份檔案自己的起訖日期檢查中間缺哪幾天；合併任務才指定完整的十年。

試跑：上傳 `samples/good.csv` 應該是 `ERROR 0｜WARNING 0｜27 天`。

## 檢查項目

- **檔案**：UTF-8 CSV（可含 BOM）或 XLSX（第一個工作表）；Big5 直接回報「不是 UTF-8」。
- **表頭**：24 欄都要有、前 5 欄（縣市、區域、氣溫、降雨機率、風速）順序固定；可以多欄。
- **逐列**：
  - 縣市用「臺」；區域是資料點所在的**一個**高雄市行政區。
  - 日期 `YYYY-MM-DD`、一天只能一列。
  - 數值欄（氣溫、最高／最低、風速、最大陣風、降水量、氣壓、相對濕度、降水時數、降雨機率）都要是數字且在合理範圍。
    - `T`、`/`、`--`、`-9.8`、`-99…` 這類代碼一律報錯，要留空並在備註寫原值。
    - 最低 ≤ 平均 ≤ 最高；最大陣風 ≥ 平均風速。
  - **降雨機率**：資料來源類型是「預報」時必填；「觀測」「再分析」時必須留空（不要用降水量推算）。
  - 資料來源類型只能是：觀測／再分析／預報／其他。
  - 高雄站編號只能是 467440 或 467441；2022 年前用 467441、之後用 467440 會給警告，提醒確認換站日期。
  - 緯度、經度在臺灣範圍；依座標算出的距離與「距真愛碼頭(km)」差超過 1 km 給警告。
  - 來源網址是完整 http(s)；擷取日期不晚於今天；必填欄位不能空白。
  - 量測值留空卻沒寫備註 → 警告。
- **缺天**：期間內少了哪幾天列成警告，不影響通過。

## 本機使用

```bash
python grade.py --file weather_guanyuan.csv --from 2016-10-06 --to 2019-12-31
```
